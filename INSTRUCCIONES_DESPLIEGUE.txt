PASO 4: CREAR USUARIO ADMINISTRADOR
═══════════════════════════════════════════════════════════════════════════════

⚠️  IMPORTANTE: Esta operación se hace UNA SOLA VEZ

1. En Firebase Console, ve a:
   Cloud Functions → Entorno de prueba de Cloud Shell

2. Ejecuta este comando (reemplaza el email):

   firebase auth:create-user \
     --email admin@appmovil.local \
     --password "AdminPassword123!" \
     --display-name "Administrador" \
     --project app-movil-psf

3. Anota el UID que devuelve (ej: abc123def456)

4. Ahora asigna el custom claim de admin:

   node -e "
   const admin = require('firebase-admin');
   admin.initializeApp();

   async function makeAdmin() {
     const user = await admin.auth().getUserByEmail('admin@appmovil.local');
     await admin.auth().setCustomUserClaims(user.uid, { admin: true });
     console.log('✅ Usuario admin creado correctamente');
   }
   makeAdmin();
   "

📱 REGISTRO Y NEGOCIO

Flujo Completo Implementado:

1️⃣  REGISTRO COMO USUARIO REGULAR
   └─ Crear cuenta con email/contraseña
   └─ Auto-login
   └─ Aparece en auditoría: "register"

2️⃣  REGISTRO COMO DUEÑO DE NEGOCIO
   └─ Widget especial con datos de negocio
   └─ Crea atómicamente: Usuario + Negocio + Catálogo
   └─ Auto-login como dueño
   └─ Aparece en auditoría: "register" con tipo "dueño"

3️⃣  SOLICITUDES DE PUBLICACIÓN
   └─ Dueño puede enviar "cambios" a su negocio
   └─ Dueño puede crear "anuncios" para su negocio
   └─ Admin aprueba/rechaza con motivo
   └─ Publicación automática al aprobar
   └─ Todo queda en auditoría

4️⃣  AUDITORÍA PERSONAL
   └─ Cada usuario ve sus propias acciones
   └─ Timestamp del servidor
   └─ No se puede eliminar

5️⃣  AUDITORÍA GLOBAL (ADMIN)
   └─ Admin ve todas las acciones del sistema
   └─ Usuario, acción, timestamp, resultado
   └─ Filtrar por tipo de acción (opcional)

═══════════════════════════════════════════════════════════════════════════════
FLUJO DE PUBLICACIÓN EN EL NEGOCIO
═══════════════════════════════════════════════════════════════════════════════

┌─ DUEÑO PUBLICA CONTENIDO
│
├─ Envía "Solicitud de Cambio"
│  ├─ Negocio ID: su negocio
│  ├─ Tipo: "cambio" (actualizar datos) o "anuncio" (nuevo anuncio)
│  ├─ Propuesta: datos nuevos
│  └─ Estado: "pendiente"
│
├─ Sistema crea registro de auditoría
│  └─ Acción: "submitRequest"
│
├─ ADMIN REVISA Y APRUEBA
│  ├─ Ve solicitud pendiente
│  ├─ Revisa cambios propuestos
│  ├─ Toca "Aprobar"
│  └─ Escribe motivo (opcional)
│
├─ Transacción en Firestore:
│  ├─ Actualiza catálogo
│  ├─ Crea versión aprobada
│  ├─ Marca solicitud como "aprobada"
│  ├─ Crea notificación para dueño
│  ├─ Crea novedad pública
│  └─ Registra en auditoría: "resolveRequest"
│
└─ Contenido ya está PUBLICADO en catálogo

SOPORTE Y TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

❌ Error: "Project not found"
$ firebase use app-movil-psf
$ firebase deploy

❌ Error: "Permission denied on /auditoria"
- Verifica que firestore.rules está desplegada
- Ejecuta: firebase firestore:rules:test

❌ Error: "Cloud Function deployment failed"
- Reinstala dependencias: npm --prefix functions ci
- Redeploy: firebase deploy --only functions

❌ Admin no puede ver auditoría
- Verifica custom claim: const user = await admin.auth().getUser('UID');
- Debe mostrar: {admin: true}
